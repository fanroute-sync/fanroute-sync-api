# 기획 및 MVP 기준

## MVP 목표

부산 공연 관람 전후의 여행 일정을 생성·편집하고, TourAPI 장소 검색과 AI 일정 생성을
지원하며, Fan Route 커뮤니티에 공유한다.

## 도메인 책임

| 도메인 | 주요 책임 |
| --- | --- |
| 사용자·인증 | Google OAuth, 프로필 |
| 공연 | 공연·공연장 정보와 공연장별 추천 장소 |
| 일정 | 여행 계획, 숙박, 날짜별 일정, 일정 항목, 일정별 AI 추천 횟수, AI 일정 생성 |
| 장소 | TourAPI 장소 검색·동기화 |
| 커뮤니티 | 정보 공유·참고 루트·동행 모집, 좋아요, 댓글 |
| 채팅 | 동행 모집 채팅. 일정 MVP와 별도 범위로 관리 |

## 일정 정책

- 여행 계획은 공연 없이도 생성할 수 있다.
- 숙소는 여러 개를 등록할 수 있으며 체크인·체크아웃 일자를 가진다.
- 관리자는 공연장별 추천 장소를 등록하고 순서와 추천 시간대(아침/점심/저녁/밤)를 지정한다.
  같은 공연장에서 열리는 서로 다른 공연은 같은 추천 장소 목록을 사용한다.
- 여러 추천 장소를 “공연 전 식사 코스”, “공연 후 관광 코스”처럼 묶어 이름과 설명을 붙일 수
  있다. 코스 항목은 장소를 직접 참조하지 않고 공연장별 추천 장소를 참조한다.
- 장소의 성격은 허용된 enum 태그로 `place_tags`에 관리한다. 추천 시간대와 순서는 장소 자체가
  아니라 공연장과 장소의 관계(`venue_recommended_places`)에 저장한다.
- 공연 자체가 어느 시간대에 속하는지 알려면 특정 회차(공연일·시각)가 확정돼 있어야 한다.
  여행 계획은 공연(concertId)뿐 아니라 관람할 특정 회차(concertScheduleId)도 선택할 수 있으며,
  선택한 회차는 반드시 선택한 공연에 속해야 한다.
- 추천 장소 조회 API(`GET /venues/{venueId}/recommended-places`)에 concertScheduleId를 넘기면,
  서버가 그 회차 시작 시각을 시간대로 환산해 가까운 시간대순으로 정렬한다. 공연과 같은 시간대로
  등록된 장소는 결과에서 제외하며, 회차의 공연장이 요청 공연장과 다르면 오류를 반환한다.
- 추천 코스 조회 API(`GET /venues/{venueId}/recommendation-templates`)도 같은 회차 시간대 필터링
  규칙을 적용한다.
- 위 두 조회 API는 공연장 자체가 존재하지 않으면 오류를 반환한다. 추천 장소·코스가 없는 것과
  공연장 ID가 잘못된 것을 구분하기 위함이다.
- 추천 장소는 벌크 임포트 API(`POST /admin/venue-recommended-places/import`)로 여러 건을 한 번에
  등록할 수 있다. 단건 등록과 같은 검증 경로를 거치며, 하나라도 실패하면 전체가 롤백된다.
- 사용자는 추천 장소를 하나씩 골라 자기 일정에 추가하고 시각은 직접 정한다.
- 이렇게 추가된 항목은 공연 연결 고정 항목이 아니라 **일반 일정 항목과 동일하게 수정·삭제**할
  수 있다.
- 선택한 공연장에 추천 장소가 없어도 별도 폴백 없이 빈 결과를 반환한다. 클라이언트는
  수동 일정 추가로 안내한다.
- 추천 장소 추가는 일정 소유권과 여행 계획의 공연장 일치를 검증한다. 공연 없이 생성된 여행
  계획에는 추천 장소를 추가할 수 없다.
- (후순위) 장소 태그와 여행 계획의 선호도(preferences)를 매칭해 추천 장소를 자동 정렬한다.
  이번 MVP에서는 관리자가 지정한 순서와 공연 회차 시간대만 사용한다.
- AI 일정 생성은 429·5xx·network timeout 같은 일시 오류만 지수 backoff로 재시도하고,
  JSON·장소·시간 검증 실패는 최종 실패 처리한다. 처리 중에도 수동 일정 추가를 막지 않는다.
- 새 여행 일정은 AI 추천 5회로 시작한다. 실패한 AI 생성과 취소된 대기 작업은 횟수를
  사용하지 않는다.
- AI 일정 생성 요청은 작업 ID를 즉시 반환하고 백그라운드에서 실행한다. 클라이언트는 작업 상태 조회 API로 완료·실패를 확인한다.
- 공식 공연 시작 시각은 추천 장소의 시간대와 별도로 공연 정보에서 관리해야 한다.
- KOPIS의 `dtguidance`(공연시간 안내) 원문은 공연 정보에 그대로 보존한다. 모든 구문을 신뢰성 있게
  해석할 수 있는 경우에만 공연 기간의 실제 날짜별 회차로 전개하며, 일부만 해석된 결과는 저장하지
  않는다. 파싱 실패 시 임의의 공연 시각을 생성하지 않고 사용자에게 시간 확인이 필요함을 표시한다.
  자동 생성 회차와 관리자 등록 회차는 출처를 구분하며, 재동기화는 자동 생성된 미확정 회차에만
  적용한다. 회차 번호는 공연 전체가 아니라 같은 공연일 안에서 시간순으로 부여한다.

## 범위 밖 또는 후순위

- 다국어, Apple·Meta 로그인
- 실시간 채팅과 실시간 공연 정보 연동
- 참고 루트의 딥링크형 일정 가져오기
- 알림 설정과 회원 탈퇴

## 기준 자료

추천 장소·추천 코스의 모델 관계, API, 운영 경계는
[`recommendation-places.md`](recommendation-places.md)에 정리한다.

- 기획 회의 2~8차 회의록
- 일정 ERD 초안(DBML)
- 와이어프레임 Rev.3

세 자료가 충돌하면 최신 화면 정책과 팀의 명시적 결정을 우선하며, 결정 전에는
이슈 또는 PR에 미결정 사항으로 기록하고 관련 담당자의 확인을 받는다.

## 커뮤니티 MVP 결정

동행 모집은 댓글 연락까지 구현한다. 채팅방 자동 생성은 채팅 도메인 도입 시, 작성자 채택과 참여 최대 5개 제한은 참여 상태 모델 도입 시 구현한다. 채택 전에는 현재 인원을 작성자 1명으로 표시한다.
